# Protocol and Compatibility

`contract/source.json` pins one exact upstream Service revision plus OpenAPI, Thread stream schema and semantic owner documents. `npm run generate` deterministically produces generated types, workspace-scope route metadata and static resource bindings. Generation is schema transformation, not a second authored workflow. Release review checks pinned identity, exact operation/path/schema sets, snapshot diffs and authored adapters. Types are compile-time contracts, not runtime validation of arbitrary AG-UI payloads or all provider behavior.

The public cutover removes obsolete workspace-prefixed business paths, ambient workspace headers for API keys, the redundant `client.http` facade, the Service secret resource, old Run SSE/notification protocols, retired queued-submission collections and alternate continuation commands. Application callers use `Agent.start/send` and one finite `Interaction` for ordinary work; complete generated resources retain specialized/admin/binary operations. Models use keys; Agents/Skills use IDs. Breaking callers migrate rather than use false compatibility aliases. The SDK cannot reshape Service state.

Transport never retries mutations. A dispatched command followed by network failure has an unknown outcome; retain the explicit idempotency key and reconcile durable identities before replay. Reads retry boundedly. HTTP errors preserve code, status, details, request ID and `Retry-After` without retaining credentials. Local timeout, abort and close affect only client-side work; remote interruption is explicit. Network failures retain Fetch's error rather than an unused SDK transport wrapper.

Validation includes exact generated operation/status dispatch checks, offline changed-contract generation, session versus API-key scope, transport and stream framing/cancel, finite interaction queue/Run identity/deadline/readback, native imported history on Thread creation and readback without follow-up reseeding, atomic resume result maps plus optional asset-capable input, explicit message continuation after failed/cancelled seals, native ordinal windows with baseline/history separation and recursive continuation preservation, TypeScript positive/negative contracts, packaged ESM/type resolution and an installed consumer. A separately managed disposable Service is needed for real authentication, idempotent 201/200 replay, queue/reassignment, waiting/resume, readback and SSE. Real browser session verification is separate from Node Fetch mocks and cannot be inferred from them. Local checks and installed packaging do not publish an SDK.
