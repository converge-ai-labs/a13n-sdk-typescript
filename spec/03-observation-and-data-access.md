# Observation and Data Access

A high-level `Interaction` yields one finite async stream for its submitted input. It binds to the incorporating Run only **after** Entry consumption, then exposes only that Run's `delta`/`boundary` frames and matching `gap`/`reset`; unrelated Run frames and unscoped `changed` signals are not presented as this interaction's output. Iteration ends on the same exact Run's completed, failed, cancelled or waiting seal, even when the SSE connection is idle. Backpressure is pull-based; at most one stream read is outstanding. Terminal completion, caller abort, `close()`, iterator break and client shutdown release the owned reader and observation; close is never a remote interrupt. Result-only use opens no SSE. The single result remains authoritative independently of transient frame delivery.

The advanced generated `threads.ref(threadId).stream.get({lastEventId,signal})` exposes one owned raw Thread-wide SSE response; no second public persistent high-level subscription exists. The authored finite interaction reuses the same typed Thread SSE parser, framing rules, and generated stream operation. Delta/boundary frames have Redis entry IDs; the parser advances its reconnect cursor only after a consumer pulls the next item. `changed`, `reset` and `gap` signals do not advance it. Buffered frames are not yielded after cancellation. The parser bounds frame size, rejects malformed UTF-8/truncated envelopes, and uses bounded reconnects; a gap-only connection cannot reset its retry budget. Raw frames are not guaranteed complete history: retained pre-attach entries can replay, but trimming/current-run filtering/gaps make losslessness impossible to promise.

`outcome.run.items()` and generated `runs.ref(id).items.get()` read committed `RunItems {run,items,position,dropped,complete}`. `position` describes the durable display readback position, `dropped` signals lost display history, and `complete` describes that readback boundary; none substitutes for Run status. On gap/reset, read the exact Run and committed Items and reconcile application state rather than inventing lost deltas. Thread's current Run, an exact Run seal, SSE EOF and an Item readback boundary are independent facts. The generated `threads.ref(id).runs` paginates Thread Run history without choosing an outcome for a submission.
