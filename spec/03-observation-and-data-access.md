# Observation and Data Access

A high-level `Interaction` yields one finite async stream for its submitted input. It binds to the incorporating Run only **after** Entry consumption, then exposes only that Run's `delta`/`boundary` frames and matching `gap`/`reset`; unrelated Run frames and unscoped `changed` signals are not presented as this interaction's output. Iteration ends on the same exact Run's completed, failed, cancelled or waiting seal, even when the SSE connection is idle. Backpressure is pull-based; at most one stream read is outstanding. Terminal completion, caller abort, `close()`, iterator break and client shutdown release the owned reader and observation; close is never a remote interrupt. Result-only use opens no SSE. The single result remains authoritative independently of transient frame delivery. The default iterator does not fetch or apply a display baseline implicitly.

The advanced generated `threads.ref(threadId).stream.get({query:{run,position},lastEventId,signal})` exposes one owned raw Thread-wide SSE response; no second public persistent high-level subscription exists. Service requires `run` and `position` together for a display coverage claim, validates Run ownership and attempt, and accepts canonical nonnegative decimal position components of at most 20 digits. These parameters are optional when no display baseline is held. The authored finite interaction reuses the same typed Thread SSE parser, framing rules, and generated stream operation. Delta/boundary frames have Redis entry IDs; the parser advances its reconnect cursor only after a consumer pulls the next item. `changed`, `reset` and `gap` signals do not advance it. Buffered frames are not yielded after cancellation. The parser bounds frame size, rejects malformed UTF-8/truncated envelopes, and uses bounded reconnects; a gap-only connection cannot reset its retry budget. Raw frames are not guaranteed complete history: retained pre-attach entries can replay, but trimming/current-run filtering/gaps make losslessness impossible to promise.

`outcome.run.items()` and generated `runs.ref(id).items.get()` read committed `RunItems {run,items,position,resume_after?,dropped,complete}`. `position` is the complete durable display coverage (`attempt-sequence`), nullable before a checkpoint. Optional nullable `resume_after` is a confirmed Redis delta ID covered by that display, not a coverage position or proof of continuity. `dropped` signals lost display history; `complete` means the Run is sealed, not that all historical Items were retained or that it completed successfully. None substitutes for Run status.

An application that has applied a snapshot may explicitly open a raw stream with that exact Run and non-null position, using `resume_after` as an optional `Last-Event-ID` hint. Covered deltas are filtered by Service before decoding, but boundaries remain observable. An absent, expired or incompatible hint falls back to retained replay filtered by coverage; its absence alone does not imply a gap. Without a coverage claim, prior `Last-Event-ID` replay behavior remains unchanged. An older-attempt claim produces `reset` before the current attempt's tail; prior-attempt progress never seeds the new attempt. The internal reconnecting reader retains any explicitly supplied coverage baseline unchanged; it does not infer a new complete position from subsequent output or gap/reset signals.

A `gap` retains its optional nullable `position`: a non-null canonical position identifies output the recovery snapshot must cover; omission/null means there is no known target. Gap/reset signals have no SSE ID and never advance the replay cursor. On gap/reset, read the exact Run and committed Items and reconcile application state rather than inventing lost deltas. Applying a snapshot and rebuilding a raw reader are explicit application operations; the SDK provides neither a UI reducer nor automatic snapshot recovery. Thread's current Run, an exact Run seal, SSE EOF and display coverage are independent facts. The generated `threads.ref(id).runs` paginates Thread Run history without choosing an outcome for a submission.
