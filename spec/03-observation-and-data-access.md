# Observation and Data Access

A high-level `Interaction` yields one finite async stream for its submitted Entry or exact Run origin. It binds to the incorporating Run only **after** Entry consumption, then exposes only that Run's `delta`/`boundary` frames and matching `gap`/`reset`; unrelated Run frames and unscoped `changed` signals are not presented as this interaction's output. Iteration ends on the same exact Run's completed, failed, cancelled or waiting seal, even when the SSE connection is idle. Backpressure is pull-based; at most one stream read is outstanding. Terminal completion, caller abort, `close()`, iterator break and client shutdown release the owned reader and observation; close is never a remote interrupt. Result-only use opens no SSE. The single result remains authoritative independently of transient frame delivery. The default iterator does not fetch or apply a display baseline implicitly.

Thread `delta.event` is an intact native AG-UI 1.0 record, not a second SDK event hierarchy. `delta.item` is required but nullable; a non-null ItemRef preserves optional nullable `ordinal`, `response_group` and arbitrary JSON-mapping `failure` metadata. A missing item is malformed, not an alternate wire format. Standard camelCase identifiers, `protocolVersion`, typed media content/source lists, unknown custom payloads (including required null), metadata and `subagentRunId` attribution pass through unchanged. The Service envelope `run_id` identifies the durable observed Run; embedded Harness `runId` or `CUSTOM.value.run_id` do not replace it. Inline child output can arrive inside the root envelope and retains separate attribution even when native message IDs collide. `SUBAGENT_FINISHED`, `SUBAGENT_ERROR` or `RUN_FINISHED` observations never independently end finite iteration: only the exact incorporating Service Run's authoritative read does. Input custom facts distinguish authored user/steering content from generated context; raw access performs no text flattening, fragment assembly or UI reduction. Service Items retain their native structured content and truncation evidence.

`textStream()` lazily projects string chunks through the same owned finite reader. It requires a trustworthy root `TEXT_MESSAGE_START` with assistant role before matching string CONTENT. Explicit child attribution (`subagentRunId`) and `metadata.display:false` are excluded. A trustworthy hidden START retains suppression until END in the same bounded active-ID state, without requiring every CONTENT/END to repeat its metadata; unrelated unknown CUSTOM events are ignored only by preview and remain native in raw access. At most eight active root message identities are retained, never transcript content; exhaustion interrupts rather than evicting. Gap/reset, ambiguous or missing START, non-string CONTENT, unmatched END, same-Service-domain delta discontinuity/attempt change and unexcluded root `CUSTOM` named `a13n.stream.fragment` raise sticky `PreviewInterruptedError`. Fragment data is an opaque JSON slice of an original CUSTOM event, not a text suffix or a source to substring-parse. Root-fragment interruption is a conservative unsupported-framing limitation, not a claim that every fragment contains text. A boundary beyond the received Service delta position interrupts preview; equal/late boundaries do not regress high-water tracking or repair missing text. A first boundary establishes only its coordinate, never a message baseline. The preview does not infer holes from Redis cursors, embedded event coordinates or valid foreign-Run filtering. It does not assemble fragments, repair a baseline or become a reducer.

Preview interruption stops only projection and releases its consumer lock, preserving the outcome observer and allowing deliberate **sequential** raw access while still open. Concurrent raw/text readers and multiple previews are rejected. A preview break also leaves observation open: callers own `try/finally { await interaction.close(); }`. Raw break closes local observation. `close()` joins cancellation of the actual transport reader and observer without requiring progress of a paused public iterator. No stream payload, projection completion or preview failure substitutes for the exact HTTP result.

The advanced generated `threads.ref(threadId).stream.get({query:{run,position},lastEventId,signal})` exposes one owned raw Thread-wide SSE response; no second public persistent high-level subscription exists. Service requires `run` and `position` together for a display coverage claim, validates Run ownership and attempt, and accepts canonical nonnegative decimal position components of at most 20 digits. These parameters are optional when no display baseline is held. The authored finite interaction reuses the same typed Thread SSE parser, framing rules, and generated stream operation. Delta/boundary frames have Redis entry IDs; the parser advances its reconnect cursor only after a consumer pulls the next item. `changed`, `reset` and `gap` signals do not advance it. Buffered frames are not yielded after cancellation. The parser bounds frame size, rejects malformed UTF-8/truncated envelopes, and uses bounded reconnects; a gap-only connection cannot reset its retry budget. Raw frames are not guaranteed complete history: retained pre-attach entries can replay, but trimming/current-run filtering/gaps make losslessness impossible to promise.

`outcome.run.items(options)` and generated `runs.ref(id).items.get(options)` share native query options `{query:{before?,after?,limit?},signal?}` and read committed `RunItems {run,items,baseline,continuation?,position,resume_after?,complete}`. Each Item has a required dense 1-based `ordinal`. `before >= 1` and `after >= 0` are mutually exclusive ordinal windows, not generic collection cursors; `limit` defaults to 200 and ranges from 1 through 500. Service owns validation and selection. The SDK forwards options without automatic page loading.

An unwindowed read (no `before` or `after`, with optional `limit`) returns the newest limit plus the **entire mutable tail**, which can exceed that limit, and `baseline:true`. Only this read supplies normalization continuation, committed `position` (`attempt-sequence`, nullable before a checkpoint), and optional nullable `resume_after`, a confirmed covered Redis delta ID. Generated `DisplayContinuation`, `FragmentState`, recursive `ObserverContinuation`, `StreamPosition` and nested schema types pass through without SDK parsing or execution-state interpretation. `RunView.display_position` is independently nullable.

Explicit historical windows have `baseline:false` and null continuation, position and resume hint. They cannot replace a live baseline, advance coverage, heal gaps or seal a live consumer. `complete` means the Run is sealed in any outcome, not that a recent or historical window contains all history. The first returned ordinal identifies earlier Items. Display history is paged rather than discarded; content can still be truncated. None of these fields substitutes for Run status.

An application that has applied an unwindowed baseline snapshot may explicitly open a raw stream with that exact Run and non-null position, using `resume_after` as an optional `Last-Event-ID` hint. Covered deltas are filtered by Service before decoding, but boundaries remain observable. An absent, expired or incompatible hint falls back to retained replay filtered by coverage; its absence alone does not imply a gap. Without a coverage claim, prior `Last-Event-ID` replay behavior remains unchanged. An older-attempt claim produces `reset` before the current attempt's tail; prior-attempt progress never seeds the new attempt. The internal reconnecting reader retains any explicitly supplied coverage baseline unchanged; it does not infer a new complete position from subsequent output or gap/reset signals.

A `gap` retains its optional nullable `position`: a non-null canonical position identifies output the recovery snapshot must cover; omission/null means there is no known target. Gap/reset signals have no SSE ID and never advance the replay cursor. On gap/reset, read the exact Run and committed Items and reconcile application state rather than inventing lost deltas. Applying a snapshot and rebuilding a raw reader are explicit application operations; the SDK provides neither a UI reducer nor automatic snapshot recovery. Thread's current Run, an exact Run seal, SSE EOF and display coverage are independent facts. The generated `threads.ref(id).runs` paginates Thread Run history without choosing an outcome for a submission.
