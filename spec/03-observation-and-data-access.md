# Observation and Data Access

A high-level `Interaction` yields one finite async stream for its submitted Entry or exact Run origin. It binds to the incorporating Run only **after** Entry consumption, then exposes only that Run's `delta`/`boundary` frames and matching `gap`/`reset`; unrelated Run frames and unscoped `changed` signals are not presented as this interaction's output. Iteration ends on the same exact Run's completed, failed, cancelled or waiting seal, even when the SSE connection is idle. Backpressure is pull-based; at most one stream read is outstanding. Terminal completion, caller abort, `close()`, iterator break and client shutdown release the owned reader and observation; close is never a remote interrupt. Result-only use opens no SSE. The single result remains authoritative independently of transient frame delivery. The default iterator does not fetch or apply a display baseline implicitly.

Thread `delta.event` is an intact native AG-UI 1.0 record, not a second SDK event hierarchy. `delta.item` is required but nullable; a non-null ItemRef preserves optional nullable `ordinal`, `response_group`, arbitrary JSON-mapping `failure` metadata and generated `MemorySource[]` evidence in `memory_sources`. Missing, null and empty source lists remain distinct; native defaulted source fields stay optional. Assistant message-END source observations become durable at the ordinary checkpoint boundary and committed reply Items retain them in `content.memory_sources`; they describe automatic delivery, not answer citations or source-content snapshots. A missing item is malformed, not an alternate wire format. Standard camelCase identifiers, `protocolVersion`, typed media content/source lists, unknown custom payloads (including required null), metadata and `subagentRunId` attribution pass through unchanged. The Service envelope `run_id` identifies the durable observed Run; embedded Harness `runId` or `CUSTOM.value.run_id` do not replace it. Inline child output can arrive inside the root envelope and retains separate attribution even when native message IDs collide. `SUBAGENT_FINISHED`, `SUBAGENT_ERROR` or `RUN_FINISHED` observations never independently end finite iteration: only the exact incorporating Service Run's authoritative read does. Input custom facts distinguish authored user/steering content from generated context; raw access performs no text flattening, fragment assembly or UI reduction. Service Items retain their native structured content and truncation evidence.

`textStream()` lazily projects string chunks through the same owned finite reader. It requires a trustworthy root `TEXT_MESSAGE_START` with assistant role before matching string CONTENT. Explicit child attribution (`subagentRunId`) and `metadata.display:false` are excluded. A trustworthy hidden START retains suppression until END in the same bounded active-ID state, without requiring every CONTENT/END to repeat its metadata; unrelated unknown CUSTOM events are ignored only by preview and remain native in raw access. At most eight active root message identities are retained, never transcript content; exhaustion interrupts rather than evicting. Gap/reset, ambiguous or missing START, non-string CONTENT, unmatched END, same-Service-domain delta discontinuity/attempt change and unexcluded root `CUSTOM` named `a13n.stream.fragment` raise sticky `PreviewInterruptedError`. Fragment data is an opaque JSON slice of an original CUSTOM event, not a text suffix or a source to substring-parse. Root-fragment interruption is a conservative unsupported-framing limitation, not a claim that every fragment contains text. A boundary beyond the received Service delta position interrupts preview; equal/late boundaries do not regress high-water tracking or repair missing text. A first boundary establishes only its coordinate, never a message baseline. The preview does not infer holes from Redis cursors, embedded event coordinates or valid foreign-Run filtering. It does not assemble fragments, repair a baseline or become a reducer.

Preview interruption stops only projection and releases its consumer lock, preserving the outcome observer and allowing deliberate **sequential** raw access while still open. Concurrent raw/text readers and multiple previews are rejected. A preview break also leaves observation open: callers own `try/finally { await interaction.close(); }`. Raw break closes local observation. `close()` joins cancellation of the actual transport reader and observer without requiring progress of a paused public iterator. No stream payload, projection completion or preview failure substitutes for the exact HTTP result.

The advanced generated `threads.ref(threadId).stream.get({query:{run,position},lastEventId,signal})` exposes one owned raw Thread-wide SSE response; no second public persistent high-level subscription exists. Service requires `run` and `position` together for a display coverage claim, validates Run ownership and attempt, and accepts canonical nonnegative decimal position components of at most 20 digits. These parameters are optional; Items reads supply no stream position, so a caller starting from Items leaves them out. The authored finite interaction reuses the same typed Thread SSE parser, framing rules, and generated stream operation. Delta/boundary frames have Redis entry IDs; the parser advances its reconnect cursor only after a consumer pulls the next item. `changed`, `reset` and `gap` signals do not advance it. Buffered frames are not yielded after cancellation. The parser bounds frame size, rejects malformed UTF-8/truncated envelopes, and uses bounded reconnects; a gap-only connection cannot reset its retry budget. Raw frames are not guaranteed complete history: retained pre-attach entries can replay, but trimming/current-run filtering/gaps make losslessness impossible to promise.

`outcome.run.items(options)` and generated `runs.ref(id).items.get(options)` share native query options `{query:{before?,after?,limit?},signal?}` and read committed `RunItems {run,items,complete}`. Each Item has a required dense 1-based `ordinal`. `before >= 1` and `after >= 0` are mutually exclusive ordinal windows, not generic collection cursors; `limit` defaults to 200 and ranges from 1 through 500. Service owns validation and selection. The SDK forwards options without automatic page loading.

An unwindowed read (no `before` or `after`, with optional `limit`) returns the newest limit plus the **entire mutable tail**, which can exceed that limit. Explicit ordinal windows read historical Items. Neither read supplies display continuation, stream position, replay hints or proof that a missing stream range is covered. Run readback also carries no display position.

Historical windows cannot advance stream coverage, heal gaps or seal a live consumer. `complete` means the Run is sealed in any outcome, not that a recent or historical window contains all history. The first returned ordinal identifies earlier Items. Display history is paged rather than discarded; content can still be truncated. None of these fields substitutes for Run status.

An application that explicitly tracks Thread stream progress may open the raw operation with that exact Run, canonical `attempt-sequence` position and optional Redis `Last-Event-ID` hint. Covered deltas are filtered by Service before decoding, but boundaries remain observable. An absent, expired or incompatible hint falls back to retained replay filtered by progress. An older-attempt claim produces `reset` before the current attempt's tail. The internal reconnecting reader retains explicitly supplied progress unchanged; it does not infer complete coverage from subsequent output or gap/reset signals.

A `gap` retains its optional nullable `position`: a non-null canonical position identifies output the recovery snapshot must cover; omission/null means there is no known target. Gap/reset signals have no SSE ID and never advance the replay cursor. On gap/reset, read the exact Run and committed Items and reconcile application state rather than inventing lost deltas. Items readback can replace a displayed preview but cannot prove Thread gap coverage. Applications needing snapshot-to-live handoff use the Session stream. Rebuilding a raw reader remains explicit; the SDK provides neither a UI reducer nor automatic snapshot recovery. Thread's current Run, an exact Run seal, SSE EOF and display coverage are independent facts. The generated `threads.ref(id).runs` paginates Thread Run history without choosing an outcome for a submission.

The native `client.api.sessions.ref(sessionId).stream.get({signal})` returns one owned `BinaryResult`, preserving HTTP status, headers, opening errors and transport cancellation. Public `sessionStream(response,{signal})` consumes that one response as `AsyncGenerator<SessionStreamFrame>`, then closes it on EOF, protocol error, abort or iterator break. It validates every known frame against the full pinned JSON Schema, including nested required fields and schema-defined constraints, while preserving native records and allowed extra fields. Standalone validators are generated alongside types, with no runtime compiler or code generation. Session snapshots can exceed the Thread parser's 1 MiB limit. Session decoding has no default SDK frame cap; callers may set a positive `maxFrameCharacters` limit in UTF-16 code units. Exceeding that chosen limit fails and closes local observation. Unknown event names are ignored before JSON parsing. Known malformed frames and explicit SSE IDs fail with `ProtocolError`. Six independent discriminants (`thread`, `items`, `delta`, `gap`, `schedule`, `occurrence`) and `SessionStreamSchemas` are generated from the pinned Session schema, including display continuation types removed from HTTP OpenAPI.

A Session `thread` frame replaces Thread state, its named current/last Runs and ordered pending/assigned entries. An `items` frame replaces that Run's Items from ordinal `first` onward; earlier Items are final, and `complete` marks its final display. Its nullable `continuation` is native display parsing state, never a Thread cursor or execution-resume token. A `delta` is provisional native AG-UI output with Thread/Run identity. A `gap` marks lost output; Service holds that Run's deltas until a covering `items` frame. The SDK forwards these records without applying them.

Every Session connection starts with a fresh snapshot and has no SSE ID or Last-Event-ID contract. The decoder performs no reconnect. A caller implementing reconnect follows the pinned policy: stop on invalid frames or 4xx refusals other than 429; otherwise use `Retry-After` for 429/503 or full jitter below `min(30s,0.5s*2^n)`, resetting the failure count after 30 seconds open. Each reconnect discards unfinished displays and replaces them with the new snapshot; Runs sealed while disconnected are read through Items. Session observation is advanced native access, independent of the finite exact-Run Interaction and its explicit successor lifecycle.

Generated `runs.ref(runId).contents.ref(contentId).get()` reads immutable native `RunContent` under its owning Run's authority. `Item.content_refs` retains IDs, byte sizes, media types, previews and truncation evidence; neither the finite reader nor text preview loads these values implicitly. Service owns the 32 KiB inline, 4 KiB preview and 16 MiB saved-value limits. Oversized JSON is exposed as a truncated `text/plain` prefix, and applications interpret `media_type` and `truncated` rather than parsing a prefix as complete JSON. Exact Run output remains independent of this display readback.
