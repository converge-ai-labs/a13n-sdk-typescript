# Observation and Data Access

`client.streamThread(workspaceId, threadId, {after?, signal?})` or `thread.stream(...)` returns a lazy async iterator over the Service's Thread SSE endpoint. Initial pull opens the response. Each `delta` or `boundary` frame carries a Redis entry ID; the iterator advances its reconnect cursor only **after** the consumer requests the next item. A `changed`, `reset` or `gap` signal carries no advancing cursor. Consumers persist the cursor only after applying the corresponding event. A signal requests durable readback; it is not a substitute for retained Items or Thread state.

The stream validates framing, event type, applicable cursor and required envelope fields. It does not pretend to validate arbitrary AG-UI payloads exhaustively. The decoder bounds frames and rejects malformed UTF-8 or truncated frames. Reconnect is bounded and never clears a previously applied cursor; a gap-only connection cannot reset its budget. Explicit `return()`, abort or `client.close()` stops local observation, not remote execution. HTTP errors remain `ApiError` and invalid frames are `ProtocolError`. `after` is a Redis stream cursor, not an old per-Run event cursor.

`run.items({after?, limit?})` reads committed `RunItems {run, items, position, dropped, complete}`. `position` is the durable display readback position; `dropped` signals loss of display history, and `complete` is about that response's readback boundary. They are not substitutes for checking Run status. On a `gap` or `reset` frame, fetch current Thread/Run and Items, reconcile application state, then choose a new stream attachment cursor explicitly. A Run's terminal status, a Thread's current Run, and stream EOF are independent observations.

`thread.runs` paginates the Thread's Run history. The SDK does not expose the retired Run SSE or notification protocol and does not fabricate exact replay after retention loss.
