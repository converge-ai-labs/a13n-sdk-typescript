# Resource Management

`client.resources` covers every operation in the pinned OpenAPI with one generated typed binding, including Agent/Thread/Run management, administration, auth, provider actions, health and binary transfers. Business collections (`agents`, `threads`, `runs`, `sessions`, `models`, `skills`, `assets`, `uploads`, `connections`, `environments`, `environmentTemplates`, `subscriptions`, `memories`, providers and others) live directly at the root. API-key workspace is implicit; these routes are not nested under `workspaces.ref(id)`. Explicit `workspaces.ref(id)` and `organizations.ref(id)` bind their own administration endpoints. The Service secret resource no longer exists. There is no redundant raw HTTP facade or alternate handwritten management graph.

Collection `list`, `pages`, `items`, `create` and local `ref` expose only actual routes. Generated wire schemas preserve request/response shapes, including one-time signing secrets on subscription creation; no catch-all action method exists. Model selectors use keys; Agent, Skill and other resources use IDs. Agent `config.model` is a Model **key**; run/request `model_settings.extra_body` and `extra_headers` are transmitted intact. A Run's settings replace Agent settings, then Model defaults overlay per Service rules; each extra object replaces its inherited object, and `{}` clears it. The SDK does not derive affinity/inference policy.

JSON operations preserve response metadata. Blob or byte streams with declared content types support binary uploads; `{file: Blob}` supports multipart. Owned downloads/raw SSE expose unbuffered bodies that callers must consume or close. Cursor collections get lazy pages/items with stable filters and repeated-cursor detection; specialized committed readbacks do not acquire fake pagination. Conditional methods require `ifMatch` where Service declares a precondition. A local reference confers no authority, and authorization/ETags/idempotency remain Service-owned.

## Model Providers and media policy

Provider/connector metadata is deployment-selected dynamic discovery, not a closed SDK whitelist. Native Model API strings and Connection schemas pass through generated bindings. MCP discovery, transports and issuer policy remain Service-owned; the SDK introduces no provider-specific client or MCP runtime.

The schema-derived Model Provider reference exposes `authorization.get()`, `authorize(body)`, `authorization.callback(body)`, `authorization.delete()` and `models.get()`. Status/disconnect retain nullable safe evidence, discovery returns the native model array, and all calls share workspace selection, session/CSRF, cancellation and non-replayed mutation behavior. Service owns grants (`read` for status, `write` for authorization changes, `run` for discovery) and restricts hosted/browser authorization to an unconfined user login. Manual workspace authorization does not imply that an API key can initiate a hosted flow. Clients follow the returned method and authorization contract; the SDK owns no OAuth browser, callback origin/client identity, credential store or token exchange.

Generated Model characteristics preserve nullable `image_input`, `video_input` byte budget and `url_input.video` native subtype support. Omitted image policy uses native preparation defaults, null disables automatic preparation, and zero image limits preserve their declared semantics. Message input uses native text/URL/Asset/JSON parts; it does not become AG-UI output parts. Service/Harness owns image preparation, video download/transformation, host/TLS enforcement and aggregate byte budgets; the SDK does not perform media I/O or infer modality support.

## Memory

`client.resources.memories` lists, creates and selects Memory resources. `client.resources.memoryProviders` manages/tests provider accounts independently of file content or provider records. File Memory is JSON text: `memory.files` supports list/create/get/replace/delete/move, and nested Unicode paths encode once. File writes use the file ETag; Memory metadata uses the Memory ETag. `memory.revisions` supports integer `ref(seq)`, read, restore and history purge. Restore undoes that change; undoing creation removes the file and can return `file:null`. It permits an omitted precondition only when the target file is absent.

`memory.records` supports list/create/search and ref(id).replace/delete, with no item GET, PATCH or record ETag; search sends its query in a POST body. Uncertain writes are not replayed. Generated `threads.ref(id).memories` supports list, conditional create, and ref(name).update/delete. Mount mutations require the **Thread** ETag. New Thread/Fork inputs accept mounts, Agent configuration accepts default mounts, and Run views retain accepted mount snapshots rather than live later Thread changes.
