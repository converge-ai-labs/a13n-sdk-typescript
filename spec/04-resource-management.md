# Resource Management

`client.api` covers every operation in the pinned OpenAPI with one generated typed binding, including Agent/Thread/Run management, administration, auth, provider actions, health and binary transfers. Business collections (`agents`, `threads`, `runs`, `sessions`, `models`, `skills`, `assets`, `uploads`, `connections`, `environments`, `environmentTemplates`, `subscriptions`, `memories`, providers and others) live directly at the root. API-key workspace is implicit; these routes are not nested under `workspaces.ref(id)`. Explicit `workspaces.ref(id)` and `organizations.ref(id)` bind their own administration endpoints. The Service secret resource no longer exists. There is no redundant raw HTTP facade or alternate handwritten management graph.

Collection `list`, `pages`, `items`, `create` and local `ref` expose only actual routes. Generated wire schemas preserve request/response shapes, including one-time signing secrets on subscription creation; no catch-all action method exists. Model selectors use keys; Agent, Skill and other resources use IDs. Agent `config.model` is a Model **key**; run/request `model_settings.extra_body` and `extra_headers` are transmitted intact. A Run's settings replace Agent settings, then Model defaults overlay per Service rules; each extra object replaces its inherited object, and `{}` clears it. The SDK does not derive affinity/inference policy.

JSON operations preserve response metadata. Blob or byte streams with declared content types support binary uploads; `{file: Blob}` supports multipart. Owned downloads/raw SSE expose unbuffered bodies that callers must consume or close. Cursor collections get lazy pages/items with stable filters and repeated-cursor detection; specialized committed readbacks do not acquire fake pagination. Conditional methods require `ifMatch` where Service declares a precondition. A local reference confers no authority, and authorization/ETags/idempotency remain Service-owned.

## Model Providers and media policy

Provider/connector metadata is deployment-selected dynamic discovery, not a closed SDK whitelist. Native Model API strings and Connection schemas pass through generated bindings. MCP discovery, transports and issuer policy remain Service-owned; the SDK introduces no provider-specific client or MCP runtime.

The schema-derived Model Provider reference exposes `authorization.get()`, `authorize(body)`, `authorization.callback(body)`, `authorization.delete()` and `models.get()`. Status/disconnect retain nullable safe evidence, discovery returns the native model array, and all calls share workspace selection, session/CSRF, cancellation and non-replayed mutation behavior. Service owns grants (`read` for status, `write` for authorization changes, `run` for discovery) and restricts hosted/browser authorization to an unconfined user login. Manual workspace authorization does not imply that an API key can initiate a hosted flow. Clients follow the returned method and authorization contract; the SDK owns no OAuth browser, callback origin/client identity, credential store or token exchange.

Generated Model characteristics preserve nullable `image_input`, `video_input` byte budget and `url_input.video` native subtype support. Omitted image policy uses native preparation defaults, null disables automatic preparation, and zero image limits preserve their declared semantics. Message input uses native text/URL/Asset/JSON parts; it does not become AG-UI output parts. Service/Harness owns image preparation, video download/transformation, host/TLS enforcement and aggregate byte budgets; the SDK does not perform media I/O or infer modality support.

## Tool discovery configuration

Generated `tool_search` contains a strict proxy-only configuration. Omitted config/mode and an empty config use Service defaults; null config and native strategy fields are invalid. Run override omission/null inherits the revision; a non-null block replaces it and empty groups disables grouping. Groups select already admitted Connection, plugin, platform and capability sources. Service owns source admission and discovery execution.

## Desktop access and control

Native `runs.ref(id).desktopAssistance.ref(callId).get()` reads Agent-requested assistance; `runs.ref(id).desktopControl.get()` reads nullable user-origin control and `.create({mount,reason})` opens its viewing context. `desktopAssistance.ref(id)` exposes `view(body,{query:{renew}})`, `control(body,{query:{renew}})`, `disconnect(body)`, `requestControl()` and `complete(body)`. These share the generated transport, permissions, workspace/authentication and no-mutation-replay policy. Metadata is separate from access responses, whose sensitive viewer credentials require `Cache-Control:no-store` handling and must stay out of logs.

Agent-requested assistance is a deferred tool call on an opted-in root Computer environment. User-origin `requestControl()` requests safe suspension and returns metadata, not input authority; Service reserves the target and seals at a complete model boundary. `control({session_id,epoch})` grants one fenced browser controller only after admission. This `session_id` is a 20–72 character browser-session token, distinct from a Service Session resource ID; epoch is an integer starting at zero. Service owns permissions, generation/epoch fences, target reservation, leases and cleanup confirmation. `disconnect()` revokes that browser's grants without answering a tool or resuming. `complete({session_id,epoch,outcome,note})` revokes grants and persists the bounded handback outcome without starting a Run. Completed-Run idle control has no resume successor. Uncertain cleanup blocks handback; expiry/disconnection does not durably unpause execution. The SDK performs no automatic renew, retry, reclaim, control or resume.

## Memory

`client.api.memories` lists, creates and selects Memory resources. `client.api.memoryProviders` manages/tests provider accounts independently of file content or provider records. File Memory is JSON text: `memory.files` supports list/create/get/replace/delete/move, and nested Unicode paths encode once. File writes use the file ETag; Memory metadata uses the Memory ETag. `memory.revisions` supports integer `ref(seq)`, read, restore and history purge. Restore undoes that change; undoing creation removes the file and can return `file:null`. It permits an omitted precondition only when the target file is absent.

`memory.records` supports list/create/search and ref(id).replace/delete, with no item GET, PATCH or record ETag; search sends its query in a POST body. Uncertain writes are not replayed. Generated `threads.ref(id).memories` supports list, conditional create, and ref(name).update/delete. Mount mutations require the **Thread** ETag. New Thread/Fork inputs accept mounts, Agent configuration accepts default mounts, and Run views retain accepted mount snapshots rather than live later Thread changes.

`client.api.memorySpaces` owns native CRUD, organization status, organization history/action and attached Session reads. A Space owns managed file Memory; selection uses `Session.memory` Space bindings rather than direct Thread mounts of that backing Memory. The first accepted business Run settles omitted Agent defaults on the Session. Run readback preserves the `MemoryMount | FrozenMemoryMount` union, including optional non-null `roots` and nullable `space_id`; authored request mounts remain `MemoryMount` and accept neither host-only field. Service freezes allowed roots and authority at Run acceptance. Session edits require the Session ETag; Space configuration edits require the Space ETag.

Manual `organizations.create()` has no body and returns HTTP 202 `SpaceOrganizationStatus`, independently of any organizer Run. Status is separate from configuration versioning. Service owns external-change counts, minimum check/cooldown delays, coalescing and execution in an isolated `memory_organization` Session. The SDK neither schedules organization nor converts admission into a finite business Interaction. Once status names an actual Run, callers may explicitly observe that exact identity.

## Diagnostics and attributed reads

Generated `findings` supports create/list/pages/items and ref(id).get/update; assessment updates require the Finding ETag. `findingAnalyses` supports list/create with an explicit creation idempotency key and native 201/200 creation/replay status. Root `findingAgent()` posts without a body. The SDK preserves native evidence, selection, assessment and nullable fields; Service owns diagnostic validation, Run selection and authorization. Agent `preset_kind` uses native `PresetKind`, including `composer`, `finding` and `memory_organizer`. Toolset keys include `traces`, `findings` and `computer`, with native Tool/Toolset descriptions.

Generated `sessions.ref(id).messageAuthors.list({query:{entry_id}})` requires 1–100 native repeated Entry-ID query values and retains nullable identity details; it is not a cursor collection. Provider discovery returns `ProviderModel[]` with native slug/display name/nullable characteristics; the obsolete `ChatGPTModel` schema is retired. `supports_model_discovery` is dynamic provider metadata.

Memory record responses retain nullable `provenance:{created,last_write,content_matches}`. Platform-confirmed attribution is best-effort, separate from provider content and remote mutation order. Nullable creation and Run/attempt/tool-call fields, current principal names, and content mismatch remain native; a matching digest does not prove absence of external edits. The SDK adds neither source-message citations nor record versions/ETags.

## Executed configuration and usage

Native `runs.list()` exposes filtered cursor pages; exact Run references expose `agent.get()` and `attempts.ref(id).get()`. `RunAgent` preserves the frozen revision and effective Agent configuration after the frozen Run override. Referenced Models, Connections and templates remain live, while Run `options.configuration` retains its separate request-level meaning. The SDK does not reconstruct execution from the current Agent head.

Native usage retains model totals plus required per-Run breakdowns. Model-request metrics and model aggregates preserve required nullable TTFT/token-speed fields and valid zero values without SSE-derived substitutes. Model catalog filters preserve exact provider and case-sensitive Model IDs; the specialized list is not cursor pagination.

`usage.context.get({query:{thread_id}})` (or exactly one `run_id`/`record_id`) preserves native `ContextUsage | null`. Service validates selector cardinality and resource visibility; callers omit unused selectors. Every non-null object requires Run/record IDs and nullable `input_tokens`, `output_tokens` and `context_window_tokens`, preserving zero. Thread/Run selection uses the latest completed main-Agent contribution, so a pending prompt is not an estimate and a later pending Run does not erase an older eligible Thread contribution. Existing resources without a contribution return HTTP 200 JSON null; missing resources return 404. An explicit record selects that contribution, including a failed or child contribution. Capacity follows current Model configuration and may be unknown. The SDK computes no totals, utilization ratio or cache subtraction.

## Environment and Skill policy

Native Agent configuration defaults `lazy_environment` to true; nullable Run overrides inherit on omission/null and replace on a boolean. Reserved identities do not prove native allocation. False prepares frozen managed instances before Harness execution; connectors remain first-use in either mode. Explicit Environment creation remains eager. Mount `working_directory` retains its native shape and is checked at execution open without automatic directory creation.

Environment mount `permission_ceiling` preserves exact native `EnvironmentAction` values. Omission retains native file/execution defaults without Computer authority; `operations:[]` grants none. Thread mount updates require the Thread ETag and affect future Runs. Native `environments.ref(id).computer.check()` is a bodyless explicit probe with `checked`, `unsupported` or `not_ready` results, not an environment-start or authority-grant operation. Agent Computer tools, mount permissions and provider readiness are independent requirements.

Retained Run `images.ref(id).get()` returns an owned unbuffered PNG/JPEG `BinaryResult`, preserving bytes, response metadata, local cancellation/close and ordinary API errors. Raw `a13n.tool_images` references and child attribution pass through unchanged. A streamed reference can precede committed publication and return 404. Images are distinct from Assets and saved JSON/text content. Download failure never replays the Computer action.

Agent `builtin_skills` preserves omission, null and empty selections. Service owns tool admission, credentials and instruction initialization before inference.

Native `skill_sync` is a mode-tagged union. Shared mode defaults to overwrite=true and cleanup=false, publishing conventional mutable names; isolated mode defaults to cache_count=128 and immutable digest-keyed packages, with zero disabling trimming. The complete Run block replaces the Agent block. Cross-mode fields are rejected by the generated types. Service owns preparation, overwrite, cleanup, caching and filesystem publication; forwarding these options adds no SDK I/O or readiness operation.
